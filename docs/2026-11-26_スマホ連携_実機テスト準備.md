## 0. 大事な前提：プレビューも本番の Firestore を使う
PR のプレビューURLは「画面（HTML/JS）だけ」別物で、データベース（Firestore）は本番と同じ1つです。
そのため **スマホ連携の実機テストには、本番 Firestore に `links` ルールを追加する必要があります**。
ルールは「追加だけ」（既存の `users` 部分は1文字も変えていない）なので、今のクラウド同期には影響しません（エミュレーターで確認済み）。

## 1. 連携コードの有効期限と不正利用対策
| 項目 | 内容 |
|---|---|
| コード | 8文字・31種類の文字（0/1/I/O/L なし）＝約8,500億通り。ブラウザの安全な乱数で生成 |
| 有効期限 | **発行から30日**で投擲を受け付けなくなる（ルールで強制）。発行時刻はサーバー時刻±10分以外を拒否するので、古い日付の偽装もできない |
| 一覧 | コードの一覧は取得不可（推測するしかない） |
| 書ける内容 | 区画名（T20・S20I・IB・START・CHANGE など決まった形）・時刻（過去7日〜未来1日）・連番だけ。他の項目や長い文字は拒否 |
| 消す・書き換え | 誰もできない（追記のみ） |
| 漏れた場合 | PC の「新しいコードにする」→ スマホに入れ直す。古いコードは PC が見なくなり、30日で書き込みも止まる |
| 個人情報 | 送るのは区画と時刻だけ。名前・Googleアカウント・端末情報は送らない |
| 残る弱点 | ログインなし方式なので、コードを知った人は投擲を書き込める（PCのPLAYに混ざる）。被害は練習記録の汚れに限られる。気になる場合は将来 App Check か匿名ログインを追加 |

## 2. 大量アクセスと費用
- 1投あたり：書き込み1回＋読み取り約2回（ルールの確認1・PCの受信1）
- 1日1,000投しても 書き込み約1,000・読み取り約2,000。無料枠（1日 書き込み2万・読み取り5万）の数％
- PC は「最後に受けた時刻の1時間前以降」だけを読む（同じミリ秒・順番の入れ替わりも取りこぼさないための重なり。同じIDは1件に）。ページを開くたびに全件を読み直さない
- スマホは貯めておける件数を最大5,000件に制限。再送は2秒→最大30秒間隔（連打しない）
- いたずらで大量に書かれた場合：無料プラン（Spark）ならその日の上限で止まるだけで請求はない。従量課金（Blaze）なら少額の請求があり得る
- **唐川さんに確認したいこと**：Firebase の料金プランが Spark か Blaze か。Blaze なら Google Cloud の「予算アラート」（例：月500円）の設定を推奨

## 3. 古いデータの削除
- ルール上、アプリからは消せない（いたずら防止のため）
- 消すとき：Firebase コンソール → Firestore → データ → `links` → 古いコードの文書を選んで削除（「サブコレクションも削除」を選ぶ）
- 量の目安：1投あたり約100バイト。10万投でも約10MB（無料枠1GBの1%）。当面は**3か月に1回、30日を過ぎたコードを手で削除**で十分
- PC 側の受信ログ（ブラウザ内 `dtl-phone-v1`）は最大3,000件で古い順に自動で消える

## 4. 既存の Firestore ルールとの差分
- `firestore.rules` は **追加のみ（+31行・削除0行）**。`users/{uid}/sessions`・`users/{uid}/meta` と「その他すべて拒否」は変更なし
- エミュレーターで確認：本人の同期データの読み書き=OK、他人・未ログイン=拒否、形の違うデータ=拒否（変更前と同じ）
- 差分は PR の「Files changed」→ `firestore.rules` で確認できる

## 5. 200S 直接入力とスマホ連携の競合
- 200S の Bluetooth は同時に1台だけ。タブレットにつないでいる間は PC に直接はつながらないので、**二重に入ることはない**
- 注意：PC の PLAY 画面を開いたまま PC のキーボードで文字を打つと、200S の入力として扱われる（以前からの仕様）。実機テスト中は PC のキーボードに触らないか、⚙ → 200S ボード設定 →「200S 自動入力」を OFF にする（スマホ連携はこのスイッチの影響を受けない）
- PC の画面で「MISS」や手入力ボタンを押すと、スマホからの投擲と混ざる。テスト中は押さない

## 6. 通信切断・再接続・再起動
| 場面 | ふるまい | 確認 |
|---|---|---|
| PC が一時オフライン | 戻ったら届いていなかった投擲が順番どおりに入る | エミュレーターで合格 |
| PC のページを再読み込み・閉じていた | 閉じていた間の投擲は「記録のみ」（PLAYには入れない）。再読み込み後は自動で LIVE に戻る | エミュレーターで合格 |
| PC が ERROR 表示 | 自動では戻らない → ページを再読み込み | — |
| スマホがオフライン | スマホ内（ファイル）に貯めて、戻ったら古い順に自動再送（最大30秒以内に再開） | **実機で確認** |
| スマホのアプリ再起動・電源OFF | 貯めた分はファイルに残り、ユーザー補助が再開したら送る | **実機で確認** |
| 再送で同じ投擲が2回届く | 同じIDなので1件になる | エミュレーターで合格 |

## 7. APK を旧版に戻す方法
- 置き場所を分けた：
  - **test-latest**＝安定版（今は v0.1.0＝送信なしの記録だけ版）
  - **test-pr**＝実機テスト中の版（v0.2.0＝PC連携あり）
- 戻し方：設定 → アプリ → 投擲ウォッチャー →「アンインストール」→ test-latest の APK を入れる → ユーザー補助で ON（ONにできなければ ︙ →「制限付き設定を許可」）
- 注意：テスト版は自動ビルドのたびに署名が変わるため、**上書きインストールではなく、必ずアンインストールしてから入れる**（v0.2.0 を入れるときも同じ）

## 8. PC 版と Firestore ルールを戻す方法
- **今は本番に何も出していない**。プレビューURLは別のアドレス（30日で自動削除）で、本番の画面・ブラウザ内データには触れない
- main に取り込んだ後に戻すとき：
  1. いちばん早い：Firebase コンソール → Hosting → リリース履歴 → 1つ前の版の「︙」→「ロールバック」（数秒で戻る）
  2. コードも戻す：GitHub で取り込みを Revert → 自動テスト → 自動で本番に反映
- ルールを戻すとき：Firebase コンソール → Firestore → ルール → 左の履歴から変更前の版を選んで「公開」（または main の `firestore.rules` を貼って公開）。`links` を消してもクラウド同期には影響しない（スマホ連携が止まるだけ）

## 9. 実機テストの手順（唐川さん）
準備（承認後）：
1. Firebase コンソール → Firestore Database → ルール → このPRの `firestore.rules` を丸ごと貼って「公開」
2. スマホ：今の投擲ウォッチャーをアンインストール → Releases の **test-pr** から APK を入れる → ユーザー補助で ON

テスト：
1. PC で **プレビューURL** を開く（Googleログインはしない＝ゲストのまま）
2. PLAY →「PHONE」→「連携コードを発行」→ 8文字が表示され、下に「LIVE」
3. スマホ：投擲ウォッチャーを開く → PC連携の欄にコードを入力 →「連携」→「● 連携中」
4. 公式アプリで COUNT-UP を1ゲーム → PC の PLAY に1投ずつ入るか、スコアが公式アプリと一致するか
5. 確認したいこと（チェック表）
   - [ ] 1投が PC に出るまでの体感時間（目安1〜2秒）
   - [ ] 24投すべて入ったか（取りこぼし・二重なし）
   - [ ] 公式アプリの動きが遅くならないか
   - [ ] START・CHANGE を押したときの PC の動き
   - [ ] スマホの Wi-Fi を切って3投 → 戻すと PC に入るか
   - [ ] スマホのアプリを終了・再起動しても続けて送れるか
   - [ ] 「PLAYに反映」を OFF にして投げると、PC の受信ログにだけ残るか
6. 結果はスマホの「記録を共有」と、PC の PHONE 画面のスクリーンショットで報告
