## 初版の範囲（仮案）

- 1人用の301 / 501 / 701。開始時の既定値は501。
- ストレートイン、オープンアウト、OB/IBとも50点。
- 1ラウンド3投。残点をちょうど0にすると、その投で終了。
- 残点を超えたらバースト。そのラウンドの減点をすべて取り消し、ラウンド開始時の残点へ戻して次ラウンドへ進む。
- オープンアウトでは残り1も有効。初版にダブルアウトの「残り1はバースト」を持ち込まない。
- 上限20ラウンド。最終ラウンドも0到達を先に判定し、届かなければラウンド上限で終了。
- 手入力と200S、MISS、直前の1投の取り消し、途中終了、再読込からの再開、履歴、JSONバックアップ、クラウド同期に対応。
- 対戦、ダブル/マスターアウト、セパレートブル、公式レーティング、アレンジ提案は後続。

上記はこのアプリの初版案であり、特定大会・公式サービスのルールの再現ではない。
ルールは開始時にセッションへ保存し、途中の設定変更で既存ゲームの意味を変えない。

## 実装の分け方

1. `game/zero-one.js`にDOMや保存に依存しない01判定処理を追加する。
2. `game/session.js`（新規）にゲーム種別、終了判定、現在ラウンド、入力可否、記録検証などの共通契約を置く。
3. `game/controller.js`（新規）に入力・undo・開始・結果確定の振り分けを置く。COUNT-UP既存処理への変更は必要最小限とする。
4. 描画をCOUNT-UPと01に分け、ボードのセグメント検出と音源は再利用する。01の得点はセッションのルールで算出し、既存のpointsを一括変更しない。

現行connector方式と非公開runtimeを維持し、新たなグローバル状態・フレームワークを導入しない。

## 保存と再計算

- 保存キー`dtl-data-v1`と既存COUNT-UPの構造は維持。新規01は`gameType: 'zero-one'`と設定`rules: { startScore, inRule: 'straight', outRule: 'open', bullMode: 'fat', maxRounds: 20 }`を追加する案。
- 古い記録でgameTypeがないものはCOUNT-UPとして扱う。未知の種別をCOUNT-UPと推測しない。
- 実際に入力した投球は、バーストを起こした投球も含めすべて残す。存在しない残りの投球をMISSで埋めない。
- dartのroundIndex/dartIndexを明示して保存する。たとえばR1の2投目でバーストしたら、次の実投はR2-D1になる。
- `score`は着弾そのものの得点。ラウンドの有効減点・残点・バーストは投球列を再生して計算する。
- 任意の1投を取り消した後も投球列から再計算。バースト投球やフィニッシュ投球の取り消しで直前状態へ戻せる設計とする。
- `status`は従来のactive/completed/abandonedを保ち、01の終了理由は別の`result.reason`（checkout / round-limit）で区別する案。途中終了はabandoned。
- 結果のキャッシュを保存する場合も再計算と一致することを検証。上限終了をクリア扱いにしない。
- 結果保存失敗時はセッションを履歴へ移さず、再試行できる状態を保持する。
- JSONの既存形式に追加フィールドで対応。CSVは既存列順を保ち、末尾にgame_type/start_score等を追加して記録の意味を識別可能にする。
- 現状のJSON取込は履歴のみを取り込む（activeは出力されるが復元されない）。初版もこの仕様を明示し、進行中ゲームの再開は同じブラウザの自動保存で保証する。
- 旧クライアントは01を取込・同期の対象外にする可能性がある。旧版が01を送受信できるとは扱わない。旧版による全履歴削除も含めた混在リスクをリリース時に整理する。

## 表示と分析

- PLAY上部にCOUNT-UP / 01のゲーム選択。投球中の変更は、現在のゲームを途中終了として保存する確認を通す。
- 01は残点を主表示し、開始点・現在ラウンド・そのラウンドの有効減点・BUST/CHECKOUTを短く表示する。
- 結果は開始点、クリア/上限終了、残点、使用ラウンド・実投数を表示。COUNT-UPの得点ランキングや自己ベストと比較しない。
- 履歴はゲーム種別を識別できるようにし、詳細にはバーストしたラウンドも表示する。
- 初版の分析画面は明示的にCOUNT-UP用とする。01が混ざって既存の平均・ベスト・実績・コーチレポートを変えないようにする。
- 01専用のPPDや上がり率は定義と分母を決めてから後続で追加。初版では公式レーティングを作らない。

## 実装順序と完了条件

1. 共通判定・種別別の検証・COUNT-UP分析の絞り込みを導入。既存テストを通す。
2. 01判定と単体テスト。301/501/701、途中ラウンド、バースト、undo、上限を網羅する。
3. ゲーム選択・残点画面・01結果・履歴を接続し、手入力で開始から保存まで確認する。
4. 200SのSTART/CHANGEと入力停止、演出、待機、再開を接続する。
5. JSON/CSV・疑似クラウド同期・保存失敗・復旧の確認。PC/モバイル、通常版/単独previewを検証する。

主要な受入例:

- 301でT20,T20,T20を入力すると121。次ラウンドのT20,T20,S1で0となり6投で終了。
- 301でT20,T20,T20の後、T20,T20,S2は最後の投球でバースト。残点121へ戻る。
- R1終了後の残点121からT20,T19で残り4、S5でバースト。S5をundoすると残り4、R2-D3を再入力できる。
- 残り20でT20は1投目のバースト。次は次ラウンドのDART 1となる。
- 残り20でS19は残り1、続くS1で終了する。
- 最終ラウンドでのチェックアウト、上限終了、両者のundoと再読込を確認する。
- クリア後の追加入力を無視し、undoすると入力を再開できる。切替待機中・演出中の追加入力も防ぐ。
- COUNT-UPと01を混在保存・再読込・バックアップ復元・疑似同期しても、従来のCOUNT-UP平均/ベスト/分析結果が変わらない。
- 01に不正な投順、終了後の追加入力、設定と合わない得点、偽のcompleted結果があれば取込/同期で拒否する。
